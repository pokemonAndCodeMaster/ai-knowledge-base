# 前端可视化与组件复用工程指南

本卡回答：前端可视化的基本原理、输入输出、上下游、代码写法，以及如何沉淀通用能力，避免每个页签风格不一致。

## 1. 前端可视化基本原理

```text
数据库事实 -> 后端聚合接口 -> 前端 API 函数 -> 页面状态 -> 图表组件 -> ECharts/Element Plus 渲染
```

每一步输入输出：

| 步骤 | 输入 | 输出 | 代码位置 |
|---|---|---|---|
| 数据库 | 表记录 | SQL rows | PostgreSQL |
| Repository | 查询条件 | 业务数据列表 | `src/<module>/repositories/` |
| Application Service | 用例参数 | DTO / PageResult | `src/<module>/application/` |
| FastAPI Router | HTTP 参数 | ApiResponse | `src/api/routers/` |
| 前端 api.ts | TS 参数 | TS 类型对象 | `features/<module>/api.ts` |
| View | 用户操作、API 数据 | 页面状态 | `features/<module>/views/` |
| 图表组件 | props | 可视化图表 | `components/*Chart.vue` |
| BaseChart | ECharts option | canvas/svg 图表 | `shared/charts/BaseChart.vue` |

## 2. 先区分三类组件

| 类型 | 例子 | 放哪里 | 能否复用 |
|---|---|---|---|
| 应用级通用组件 | `AppPageHeader`、`AppTable`、`AppDialog` | `shared/components/` | 全站复用 |
| 可视化基础组件 | `BaseChart`、`MetricCard`、`TrendChart` | `shared/charts/` | 全站复用 |
| 业务组件 | `TaskStatusChart`、`VersionSelector` | `features/*/components` 或 `widgets/` | 业务内或跨业务复用 |

判断是否上提：

- 只在一个页面用：留在页面同目录。
- 同一模块多个页面用：放 `features/<module>/components/`。
- 两个以上模块用且有业务语义：放 `widgets/`。
- 三个以上模块用且无业务语义：放 `shared/`。

## 3. 统一风格靠什么

统一风格不是靠每个人“自觉”，而是靠公共组件和主题。

```text
shared/styles/tokens.css       # 颜色、间距、字体、阴影
shared/charts/chartTheme.ts    # 图表颜色、tooltip、legend、grid
shared/components/AppTable.vue # 表格统一分页/空状态/loading
shared/components/AppCard.vue  # 卡片统一边距/标题/操作区
shared/components/StatusTag.vue # 状态颜色统一
```

示例：状态颜色统一。

```ts
export const TASK_STATUS_META = {
  pending: { label: '待处理', color: 'info' },
  running: { label: '运行中', color: 'primary' },
  failed: { label: '失败', color: 'danger' },
  completed: { label: '完成', color: 'success' },
} as const
```

所有页面都用 `StatusTag`，不要每个页面自己写一套状态颜色。

## 4. 图表复用的三层结构

```text
BaseChart: 封装 ECharts 生命周期
  -> 通用 Option Builder: 构造折线图/柱状图/饼图配置
    -> 业务 Chart: 把业务数据映射到通用 option
      -> View: 调 API，传数据
```

代码位置：

```text
shared/charts/BaseChart.vue
shared/charts/options.ts
features/llm-qc/components/TaskStatusChart.vue
features/llm-qc/views/TaskDashboard.vue
```

好处：

- ECharts 初始化、销毁、resize 只写一次。
- tooltip、颜色、legend 风格只配一次。
- 业务组件只表达“这是任务状态图”，不会被 ECharts 细节污染。

## 5. 表格复用

质检平台大量页面都是表格、筛选、分页、操作按钮。

推荐抽象：

```text
AppTable.vue
  props:
    rows
    loading
    total
    page
    size
  emits:
    page-change
    size-change
```

业务页面仍保留自己的列定义和操作逻辑，不要把所有业务表格都塞成一个超级组件。

复用边界：

- 通用：loading、分页、空状态、密度、表头样式。
- 不通用：任务运行按钮、版本激活按钮、评测报告下载按钮。

## 6. 视图页面标准结构

每个业务页面尽量长得像这样：

```vue
<template>
  <AppPage>
    <AppPageHeader title="大模型质检任务" />
    <TaskFilterForm @search="handleSearch" />
    <TaskStatusChart :items="summary.items" />
    <TaskTable
      :rows="tasks"
      :loading="loading"
      @run="handleRun"
      @page-change="handlePageChange"
    />
  </AppPage>
</template>
```

页面负责：

- 调 API。
- 管 loading/error。
- 管筛选、分页、弹窗开关。
- 把数据传给子组件。

子组件负责：

- 渲染 UI。
- 发事件。
- 不直接调 API。

## 7. 可视化接口怎么设计

不要给每张图都设计一个后端接口，也不要把所有图塞到一个巨大接口。

推荐：

| 场景 | API |
|---|---|
| 页面首屏概览 | `GET /api/v1/llm-qc/dashboard/summary` |
| 任务列表 | `GET /api/v1/llm-qc/tasks` |
| 单任务详情 | `GET /api/v1/llm-qc/tasks/{id}` |
| 单任务事件 | `GET /api/v1/llm-qc/tasks/{id}/events` |
| 趋势图 | `GET /api/v1/llm-qc/metrics/task-trend?start=&end=` |
| 通道耗时 | `GET /api/v1/llm-qc/metrics/channel-latency` |

接口返回业务数据，前端决定图表形态。

## 8. 长期维护约束

- 一个业务页面超过 300 行，拆组件。
- 同一个图表 option 构造重复 2 次，提取 builder。
- 同一个 UI 状态颜色重复 2 次，提取状态 meta。
- 同一个 API 错误处理重复 1 次，放到 HTTP client。
- 图表组件不得发 HTTP 请求。
- 页面不得直接写 ECharts 初始化。
- 后端不得返回 ECharts option。
