# 质检页签端到端开发流程指南

本卡给出“从环境配置到跑通一个完整页签”的开发流程。示例模块使用 `llm-qc`，其他模块按同样模式复制。

## 0. 成功标准

一个页签算跑通，至少满足：

1. 浏览器能访问页面，例如 `/llm-qc/tasks`。
2. 页面能调用前端 `api.ts`。
3. 前端请求能到后端 `/api/v1/llm-qc/tasks`。
4. 后端 router 能调用 Application Service。
5. Service 能调用 Repository 或已有 Python 类。
6. Repository 能从 PostgreSQL 拿到数据。
7. 页面能展示表格或图表。
8. 有 smoke/e2e 或至少 API 级验证。
9. 新增模块和关键约束回写 wiki。

## 1. 环境准备

```text
POSTGRES_USER=...
POSTGRES_PASSWORD=...
```

前端：

开发态访问：


## 2. 第一步：定义页面要展示什么

先写清楚这个页签的产品意图，不要直接写代码。

示例：大模型质检任务页。

| 区域 | 内容 | 数据来源 |
|---|---|---|
| 顶部指标 | 总任务数、运行中、失败、完成 | `/dashboard/summary` |
| 状态图 | 任务状态分布 | `/dashboard/summary` |
| 筛选区 | 任务名、状态、版本、时间范围 | 前端表单 |
| 表格 | 任务列表、状态、进度、创建时间、操作 | `/tasks` |
| 操作 | 运行、重试、取消、查看详情 | `/tasks/{id}/run` 等 |

输出物：页面字段清单和 API 清单。

## 3. 第二步：后端 Schema

文件：

```text
src/api/schemas/llm_qc.py
```

示例：

```python
from pydantic import BaseModel


class TaskDTO(BaseModel):
    id: int
    name: str
    status: str
    progress: float
    created_at: str


class TaskQuery(BaseModel):
    page: int = 1
    size: int = 20
    status: str | None = None
```

约束：

- Schema 面向 API，不等同于数据库表。
- 不把所有数据库字段原样暴露给前端。
- 字段名要稳定，因为前端会依赖。

## 4. 第三步：Repository

文件：

```text
src/llm_qc/repositories/task_repository.py
```

职责：只写 SQL 和数据映射。

```python
class TaskRepository:
    def __init__(self, db):
        self.db = db

    def search(self, page: int, size: int, status: str | None = None) -> dict:
        ...
```

输入：查询条件。

输出：`{"items": [...], "total": 100, "page": 1, "size": 20}`。

约束：

- 不判断任务能不能运行。
- 不调用已有 Python 业务类。
- 不拼接不可信 SQL 字符串，参数用 psycopg2 params。

## 5. 第四步：Application Service

文件：

```text
src/llm_qc/application/task_service.py
```

职责：编排用例，复用已有 Python 类。

```python
class LlmQcTaskService:
    def __init__(self, repository, checker):
        self.repository = repository
        self.checker = checker

    def list_tasks(self, page: int, size: int, status: str | None = None):
        return self.repository.search(page=page, size=size, status=status)

    def run_task(self, task_id: int):
        task = self.repository.get(task_id)
        result = self.checker.run(task["clip_id"], task["version"])
        self.repository.update_result(task_id, result)
        return self.repository.get(task_id)
```

这里的 `checker` 就是你们已有、成熟、封装良好的 Python 类实例。

约束：

- 编排可以调用多个 repository 和多个已有 Python 类。
- 业务状态迁转放这里或 domain 层，不放前端。
- 对前端返回 DTO，不返回复杂内部对象。

## 6. 第五步：后端 Router

文件：

```text
src/api/routers/llm_qc.py
```

职责：HTTP 入口。

```python
from fastapi import APIRouter, Depends, Query

router = APIRouter(prefix="/api/v1/llm-qc", tags=["大模型质检"])


@router.get("/tasks")
def list_tasks(
    page: int = Query(1, ge=1),
    size: int = Query(20, ge=1, le=100),
    status: str | None = None,
    service = Depends(get_llm_qc_task_service),
):
    data = service.list_tasks(page=page, size=size, status=status)
    return {"code": 0, "message": "success", "data": data}
```

还要在 `src/api/app.py` 注册 router：

```python
from src.api.routers import llm_qc

app.include_router(llm_qc.router)
```

约束：

- Router 不直接 new 复杂业务类。
- Router 不写 SQL。
- Router 不关心前端怎么展示。

## 7. 第六步：前端类型

文件：

```text
src/frontend/src/features/llm-qc/types.ts
```

```ts
export interface Task {
  id: number
  name: string
  status: string
  progress: number
  createdAt: string
}

export interface TaskQuery {
  page: number
  size: number
  status?: string
}

export interface PageResult<T> {
  items: T[]
  total: number
  page: number
  size: number
}
```

约束：

- 类型字段要和后端响应一致。
- 中期通过 OpenAPI 生成，早期可以手写，但要跟 Swagger 对齐。

## 8. 第七步：前端 API

文件：

```text
src/frontend/src/features/llm-qc/api.ts
```

```ts
import { request } from '@/shared/api/http'
import type { PageResult, Task, TaskQuery } from './types'

export function getTaskList(params: TaskQuery) {
  return request.get<PageResult<Task>>('/api/v1/llm-qc/tasks', { params })
}

export function runTask(taskId: number) {
  return request.post<Task>(`/api/v1/llm-qc/tasks/${taskId}/run`)
}
```

约束：

- 页面不直接 axios。
- 一个 feature 的 API 函数放在本 feature 内。
- API 函数名用动词开头：`getTaskList`、`runTask`、`retryTask`。

## 9. 第八步：前端 View

文件：

```text
src/frontend/src/features/llm-qc/views/TaskListView.vue
```

```vue
<template>
  <section>
    <TaskTable
      :rows="tasks"
      :loading="loading"
      @run="handleRun"
    />
  </section>
</template>

<script setup lang="ts">
import { onMounted, ref } from 'vue'
import { getTaskList, runTask } from '../api'
import TaskTable from '../components/TaskTable.vue'
import type { Task } from '../types'

const tasks = ref<Task[]>([])
const loading = ref(false)

async function loadTasks() {
  loading.value = true
  try {
    const page = await getTaskList({ page: 1, size: 20 })
    tasks.value = page.items
  } finally {
    loading.value = false
  }
}

async function handleRun(task: Task) {
  await runTask(task.id)
  await loadTasks()
}

onMounted(loadTasks)
</script>
```

约束：

- View 管数据加载和用户动作。
- 表格、图表、弹窗拆成子组件。
- View 超过 300 行就拆。

## 10. 第九步：前端 Router

文件：

```text
src/frontend/src/features/llm-qc/routes.ts
```

```ts
export const llmQcRoutes = [
  {
    path: '/llm-qc/tasks',
    name: 'llm-qc-tasks',
    component: () => import('./views/TaskListView.vue'),
    meta: { title: '大模型质检任务' },
  },
]
```

在总路由中注册：

```ts
import { llmQcRoutes } from '@/features/llm-qc/routes'

export const routes = [
  ...llmQcRoutes,
]
```

约束：

- 路由 `meta.title` 作为菜单来源。
- 不单独维护一份菜单配置。

## 13. 每次开发必须考虑什么

- 数据从哪里来：PostgreSQL、已有 Python 类、文件、外部服务。
- 谁编排：Application Service。
- 谁持久化：Repository。
- 谁暴露给前端：FastAPI Router + Schema。
- 前端页面放哪里：`features/<module>/views/`。
- 前端复用组件放哪里：本模块 `components/`、跨模块 `widgets/`、全站 `shared/`。
- 是否需要图表：后端返回业务数据，前端构造 ECharts option。
- 是否需要跨页面状态：需要才用 Pinia。
- 是否需要写知识卡：新增模块、接口约定、坑点、公共组件都要沉淀。
