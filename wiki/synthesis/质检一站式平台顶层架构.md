# 质检一站式平台顶层架构

本卡是平台知识与设计的唯一总入口，只保存跨模块共享的边界、能力和导航。模块专用业务流程下沉到各模块 Hub。原始宪法见 [[06_质检一站式平台顶层架构|NotebookLM 顶层架构原文]]。

## 平台目标

用统一前后端门面承载四类质检业务：人工质检、大模型质检、自动化质检、专题数据质量。统一的是工作台、交互语言与公共基础能力；各模块仍保持业务模型、表与流程边界。

## 模块架构入口

| 模块 | 定位 | 成熟度 | 架构 Hub |
|---|---|---|---|
| 人工质检 | 数据集交付、标注、验收、返修与人力运营闭环 | 样板设计，部分实施中 | [[质检一站式平台人工质检模块整体架构]] |
| 大模型质检 | 生产任务与版本配置管理，衔接六通道生产状态 | 样板设计，正向设计中 | [[质检一站式平台大模型质检模块整体架构]] |
| 自动化质检 | 规则引擎与自动执行 | 仅冻结边界 | [[质检一站式平台自动化质检模块架构]] |
| 专题数据质量 | 专题监控、分析与报表 | 仅冻结边界 | [[质检一站式平台专题数据质量模块架构]] |

## 全局共享能力

只有被两个及以上模块复用、或必须全平台一致的设计才放在这里：

- **统一工作台壳层**：模块导航、用户与权限、全局搜索、帮助入口、环境与数据新鲜度提示。
- **共享交互组件**：筛选栏、保存视图、数据表、状态标签、详情抽屉、批量操作、二次确认、执行结果与错误反馈。
- **共享异步语义**：区分请求已提交、处理中、部分成功、失败、等待回查和最终状态；不能把同步响应当作最终事实。
- **共享危险操作范式**：高风险批量操作优先采用 `preview → confirm → execute → refresh`；普通 CRUD 不强套。
- **共享权限原则**：前端负责可见性与可用性，后端才是授权边界；按模块等级授权，不做每按钮一个布尔权限。
- **共享前后端契约**：Vue 组件只调用 API 封装；请求/响应有 TypeScript 类型；FastAPI 用 Pydantic 校验；错误使用语义化 HTTP 状态。
- **共享工程边界**：Router 不拼 SQL，Repository 集中数据访问；跨模块调用经公开服务边界，不直接穿透 Repository。

## 前端统一信息架构

```text
质检一站式平台
├── 平台总览                 跨模块工作量、风险、阻塞与待办
├── 人工质检
│   ├── 交付中心
│   ├── 验收中心
│   └── 人力与分组
├── 大模型质检
│   ├── 生产任务
│   └── 版本配置
├── 自动化质检               待设计
└── 专题数据质量             待设计
```

前端按用户任务组织，不按数据库表或后端目录组织。当前 Demo 设计入口为 [[质检一站式平台前端Demo设计计划]]。

## 上移与下沉规则

1. 两个模块出现相同问题时，先比较语义；确认可复用后上移平台层。
2. 平台层只定义公共契约和最小组件 API，不吞并模块业务规则。
3. 人工质检的采样、通过/打回、人力归属只留在人工模块。
4. 大模型质检的六通道状态、kill/clean、游标分页与版本冻结只留在大模型模块。
5. 未设计模块只记录边界和待确认问题，不从两个样板模块类推出不存在的业务。
