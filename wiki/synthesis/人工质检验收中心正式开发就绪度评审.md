## 正式开发前必须补齐的架构契约

### 1. 查询与选择

模块端点接收统一 `QuerySpec`：过滤、排序、分页、展开维度、字段投影和聚合。批量操作接收 `SelectionSpec`：

```text
mode: explicit | filtered
explicit_ids: []
filter_snapshot: QuerySpec | null
excluded_ids: []
leaf_dimension: task | date | group | annotator | scene
```

服务端重新解析权限和数据范围；不能信任前端提交的行内容。

### 2. 预览与执行

大范围选择不再把海量 task_ids 暴露给前端。preview 返回短期 `preview_id`、输入摘要、数据版本、明细分页、警告和过期时间。execute 提交 `preview_id + excluded_preview_item_ids + override`；服务端校验预览归属、权限、过期、数据版本和任务状态。

这不是通用分布式事务系统，但需要一份验收操作审计和短期预览存储。可以先用 PostgreSQL 表，后续高并发再迁移 Redis。

### 3. UI 配置持久化

需要公共/个人配置资源：`table_view`、`dashboard_layout`、`dashboard_card`。保存列、筛选、排序、宽度、列组、展开维度、卡片布局和图表定义。数据源和指标必须来自后端注册表，禁止卡片配置携带任意 SQL。

### 4. 数据工作台后端聚合

任务聚合行和日期/组/人员/scene 子行由后端查询生成。前端不下载全部快照后自行聚合。建议端点：

```text
GET  /api/v1/manual-qc/acceptance/tasks
GET  /api/v1/manual-qc/acceptance/tasks/{delivery_id}/breakdown
POST /api/v1/manual-qc/acceptance/analysis/query
GET  /api/v1/ui/metrics?module=manual-qc.acceptance
```

## 技术决策建议

### 表格

已明确不接受商业授权。采用 MIT 许可的 TanStack Table + TanStack Virtual 构建无样式数据内核，自研选择、布局、筛选编辑、导出、聚合和分析层；不得误以为基础 `table` 或 Element Plus `el-table` 能低成本覆盖全部能力。卡片布局使用 MIT 许可的 GridStack，图表使用 ECharts。

### 卡片布局

使用 GridStack 承担拖动、缩放、响应式网格和布局序列化；Vue 负责卡片内容生命周期。ECharts 继续作为图表原子。布局配置由后端保存，不只写 localStorage。

## 建议纵切开发顺序

### Gate 0：决策与契约冻结

1. 表格引擎授权决策；
2. `QuerySpec`、`SelectionSpec`、preview/execute Schema；
3. Delta fake 契约与真实字段待办；
4. UI 布局/卡片持久化模型；
5. 任务、日期、组、人员、scene 的聚合映射。

### Slice 1：前端基础与只读验收队列

初始化 Vue3 + TypeScript + Vite；落 AppShell、路由、权限门、DataWorkbench、DashboardLayout；用 mock API 实现任务聚合、按天展开、父子选择联动、筛选、排序、显隐、宽度、布局保存和视口横向滚动。

### Slice 2：后端统计只读链

实现 SnapshotRepository、统计聚合、任务/日期 breakdown、QuerySpec 和分析查询 API；前端从 mock 切换到真实接口。

### Slice 3：验收分配闭环

实现 sampler、preview 存储、约束求解预览、局部排除/覆盖、fake Delta execute、回查和审计；覆盖全成功、部分失败、重复执行。

### Slice 4：通过打回闭环

实现 PassRule、PENDING 护栏、规则预览、EXECUTE 权限、fake Delta 通过/回滚和回查。

### Slice 5：卡片分析与真实外部联调

接入指标注册表、分析卡片、公共/个人布局、Excel 导出；获得真实 Delta 与 SSO 参数后完成联调。
