# 知识库高保真摄入管线 (High-Fidelity Ingestion Pipeline)

## 🎯 解决的问题

在通过 Agent 摄入（Ingest）长篇幅文档或代码配置时，大模型天生倾向于**“高度抽象化”**。如果让 Agent“边读通篇材料边写 5 种知识卡片”，极易发生 **Lost in the Middle（中间迷失）**，导致具体的代码片段、边缘报错和硬性参数被总结成一句废话。

## 🏗️ 核心解法：Map-Reduce 范式与防篡改护栏

为了实现 100% 保真，本知识库的 `[ingest]` 机制经过了彻底的重构，不再是“一口吞”，而是被拆解为物理脚本和 Agent 规范相结合的工业级流水线。

### 阶段 0：AST 语义分块 (Pre-process)
- **工具**：[[chunk_raw脚本]]
- **逻辑**：不让大模型看全篇。用脚本将长篇 Markdown 按 `H1`/`H2` 标题切碎成 `.chunks/` 临时文件。
- **目的**：保证每次送进 Context 的都是字数可控、逻辑完整的单一章节，消除 Lost in the Middle 现象。

### 阶段 1：大纲扫描 / Map (Pass 1)
- **动作**：Agent 逐个读取 Chunk，**严禁立刻写卡片**。
- **输出**：输出一份《摄入清单 (Checklist)》，像做目录索引一样，将文中的新概念、坑点、操作规范盘点出来。
- **目的**：强迫大模型在阅读阶段专注于“信息拾荒”（类似于 gbrain 的 Atoms 提取），避免在读和写之间产生资源竞争。

### 阶段 2：定向编纂 / Reduce (Pass 2)
- **动作**：根据大纲，逐张卡片聚焦编写。
- **护栏**：引入 **Direct Quote（原文快照）** 原则（见 `schema.md`）。
  - 对于 `pitfall`、`norm`、`code_module` 卡片，禁止用自然语言概括代码逻辑！
  - 必须使用 `> 引用自原文：` 或 ````代码块```` 从 Raw 数据中 1:1 照搬硬性细节。

### 阶段 3：交叉对账 / Validate (Pass 3)
- **动作**：Agent 写完卡片后，进行反思闭环。
- **检验标准**：“如果 Raw 资料被删了，仅靠这些卡片能否无损重现当初的代码环境？”若有遗漏，打回重写。

## 📊 设计借鉴

这套工作流深度借鉴了我们在 2026 年调研的知识管理项目：
- 借鉴自 **gbrain**：`Atoms提取` 思路（先提炼原子级清单，再组装）与 `Suspected-Contradictions`（比对护栏）。
- 借鉴自 **Yuxi**：`Semantic Chunking` 思路（带 Context Path 的语义分块器，防止切断代码块）。

> ⚠️ 关联规范：[[schema.md]] 中的 Direct Quote 护栏。

## NotebookLM 原始文件入口

NotebookLM 的内容 RPC 可能保留语义却破坏 Markdown 结构。涉及全部 source 无损摄入时，先执行 [[NotebookLM来源无损导出与摄入规范]]，取得原始文件、Manifest 与 SHA-256，再进入本卡的 Map-Reduce 管线。
