# 大模型质检生产任务工作台前端设计

共享交互底座：[[质检平台统一数据工作台组件设计]]、[[质检平台可配置卡片布局组件设计]]。

## 2026-07-05 业务模型纠偏

此前“六通道并行、任务创建后版本不可变”不再作为前端业务模型。当前决策如下：

- 一个生产任务组包含多条 case；工作台默认展示任务组，按 case 展开；
- 通道存在生产顺序和依赖，直至最终模型推理；每个通道选择版本，`-1/不生产` 表示跳过；
- 允许有权限的用户修改任务组各通道版本，并从指定通道回滚后重跑；这会产生版本变更与操作审计，不静默覆盖历史结果；
- 批量操作包括终止、清理、指定通道回滚、修改通道版本、生成数据集；
- 结果管理选择已产出的任务/case 生成数据集。训练集/评测集划分由数据集管理页负责，不在生产任务页提前固化。

## 创建任务的三种输入模式

| 输入模式 | 已有信息 | 默认行为 |
|---|---|---|
| 选择平台数据集 | 数据集已包含前置通道结果与版本 | 前置通道默认“复用数据集结果”，重点选择 Prompt 和模型版本；也允许显式填写其他通道版本重产 |
| JSONL OBS 路径 | JSONL 提供目标 case 与部分通道版本/结果 | 从 JSONL 刷写可复用通道信息，补 Prompt 和模型版本；显式填写的通道版本触发该通道重产 |
| 上传 JSON/JSONL 文件 | 大模型数据集格式文件 | 校验 case 后由用户选择各通道版本正常生产 |

创建预览必须展示：case 数、输入来源、各通道的“复用/生产/跳过”、版本、依赖关系和预计影响。通道回滚预览必须展示下游失效范围。

## 页面任务

工作台覆盖三类用户任务：

1. 创建生产任务：表单创建或 JSON/JSONL 文件上传，指定任务名、slice 范围和六通道版本；
2. 任务管理：概览、分组、筛选、双向游标分页、六通道进度、kill/clean、软删除和回收站；
3. 生产结果管理：按任务与通道查看产物数量、成功/失败、输出位置、失败原因和重试/清理操作。

## 核心护栏

- 六通道为 `raw_img / label / pkl / video / prompt / inference`；
- 任务创建时冻结六通道版本，后续版本配置变更不追改历史任务；
- 任务级 status 由六通道 status 派生，页面不直接修改；
- kill/clean 显示作用通道、任务数、风险和部分失败；
- 永久删除只能作用于回收站中的软删除任务。

## 交互布局

顶部状态漏斗和筛选；中部任务表每行显示六通道状态与主动作；详情使用抽屉/工作区展示通道结果。创建任务使用表单/文件两个 Tab，切换时清理另一 Tab 的输入。
