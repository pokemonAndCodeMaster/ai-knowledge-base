# 人工质检验收分配预览闭环设计

← [[人工质检验收第一纵切架构枢纽]]。业务配额：[[质检平台-验收采样配额与任务选择设计]]。页面状态：[[质检平台-人工质检验收中心前端设计]]。

## 用户链路

```text
勾选任务/日期
→ POST assignment/preview
→ 服务端解析 SelectionSpec
→ 查询仍有未分配量的日期单元
→ 计算 Good/Bad 配额
→ 冻结 preview_id、选择、规则、结果和 source_version
→ 前端展示摘要、明细、警告与有效期
→ 选择变化时前端立即收起旧预览
```

本阶段不调用 Delta。“确认分配”保持禁用，避免把配额计算成功冒充外部执行成功。

## SelectionSpec

- `mode=explicit`：接受任务 ID 或 `{task_id}-date-{YYYY-MM-DD}`；任务 ID 在后端展开为仍有可用量的日期单元。
- `mode=filtered`：携带完整 `filter_snapshot`，后端重新执行白名单过滤；不相信前端提交的行数据。
- `excluded_ids`：可排除任务或日期单元，为后续跨页全选和局部排除保留契约。
- 当前实现 `task/date`；`group/annotator/scene` 明确拒绝，不静默降级。

## Ratio 配额规则

首个可执行规则为 Ratio：输入可选目标量与 Good 比例。可用量取 `annotation_submitted - acceptance_allocated`；Good 来自 `option_annotation.GOOD - good_allocated`，剩余可用量归 Bad，保证 `Good 可用 + Bad 可用 = 总可用`。

当一类不足时由另一类补足并返回警告；总量不足时返回 shortage。日期单元间使用“整数部分 + 最大余数 + 稳定 ID 排序”分摊，保证容量不超限、总和守恒、重复运行结果稳定。

## PostgreSQL 预览

`t_qc_operation_preview` 保存创建人、SelectionSpec、规则请求、完整结果、source_version、状态和过期时间。默认有效期 30 分钟；读取必须同时匹配 `preview_id + created_by`，过期或非 READY 统一视为不可用。

`source_version` 由各冻结日期单元的 ID、可用量和 computed_at 生成。后续 execute 必须重新校验版本和任务状态，不能直接信任旧预览。

## 前端组件边界

- `useAssignmentPreview`：生成、加载、错误、选择签名和失效；
- `AssignmentPreviewPanel`：只展示服务端结果；
- `AcceptanceQueueView`：编排 DataWorkbench 与预览，不计算配额；
- `DataWorkbench`：在真实用户选择事件后发出叶子 ID，避免渲染引起伪 selection-change。
