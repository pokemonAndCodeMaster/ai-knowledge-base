# 搜索质量闭环 (Search Quality Loop)

## 核心概念

[[CodeGraph项目]] 中建立了一套极其严格的**代码搜索质量验证体系**。每当新增一种语言支持或修改检索逻辑时，必须通过 7 层验证闭环才能合并。

## 验证体系（7 层 Test Battery）

> 引用自原文：
> 1. **`codegraph_explore` 深度探索**（最重要）：5 种以上查询类型验证
> 2. **`codegraph_search` 符号查找**：BM25 排名验证
> 3. **`codegraph_callers/callees` 调用链**：确认调用边双向存在
> 4. **`codegraph_impact` 变更影响**：确认影响半径非空
> 5. **边提取质量**：`contains > calls > imports > extends > implements` 排序验证
> 6. **节点提取完备性**：每种语言必须提取 `class`, `method`, `function`, `import` 等
> 7. **真实世界 LLM Prompt 模拟**：8 种常见问题模式

## Agent A/B 验证方法论

> 引用自原文（CLAUDE.md）：
> "**Agent A/B** (`scripts/agent-eval/run-all.sh <repo> "<Q>"`): with vs without codegraph, **≥2 runs/arm** (run-to-run variance is large — never conclude from n=1). Record **duration, total tool calls, Read, Grep**."

关键：
1. **最少 4 runs/arm**，报告中位数
2. **不要只看确定性 Probe**：probe 和真实 Agent 行为经常不一致（被自适应骨架化的 Dead End #6 证实）
3. **Pre-warm daemon**：Agent 启动时 MCP 如果还没连接好，Agent 会回退到 grep/read

## 通过标准

> 引用自原文：
> "**Pass bar:** a normal flow question reaches **~0 Read/Grep within the repo's explore-call budget**, runs **faster** than without-codegraph, and shows **no regression on a control repo**."

## 核心指标

CodeGraph 唯一关心的终极指标：

> 引用自原文：
> "The mechanism that drives everything here: **an agent falls back to Read/Grep the instant a codegraph answer is insufficient.** So every change is judged by one question — is codegraph's answer sufficient enough to *stop* the agent from reading?"

## 对知识库的启发

这套搜索质量闭环为我们的知识检索系统提供了可借鉴的**评测范式**：
1. 定义明确的"通过标准"（如：召回率 > 90%，无遗漏关键 pitfall 卡片）
2. 使用真实的下游任务（如"帮我修一个 xxx bug"）作为测试 prompt
3. **永远用真实 Agent 行为验证，不要只看工具级 probe**
