# 混合模态知识提取 (Hybrid Extraction)

## 核心思想

[[Graphify项目]] 证明了一个重要范式：**不同类型的知识应该用不同的提取方式**，然后在图层面统一。

> 引用自原文（how-it-works.md）：
> "**Pass 1 — Code structure (free, no API calls):** Tree-sitter parses your code files and extracts classes, functions, imports, call graphs, and inline comments. This runs locally with no LLM involved."
> "**Pass 3 — Docs, papers, images (Claude subagents, costs tokens):** Claude runs in parallel over markdown, PDFs, images, and transcripts."

## 提取策略矩阵

| 内容类型 | 提取方式 | 成本 | 置信度 |
|----------|---------|------|--------|
| 代码 | Tree-sitter AST（本地） | 零 | EXTRACTED |
| SQL | 确定性解析器（本地） | 零 | EXTRACTED |
| 视频/音频 | faster-whisper 本地转录 | 零 | EXTRACTED |
| Markdown/HTML | LLM 语义提取 | Token | INFERRED |
| PDF | LLM 语义提取 | Token | INFERRED |
| 图片 | LLM 视觉理解 | Token | INFERRED |

## 置信度分级体系

> 引用自原文（how-it-works.md）：
> - **0.95** — near-certain (explicit cross-file reference, one plausible target)
> - **0.85** — strong evidence (naming + context align)
> - **0.75** — reasonable (contextual but not explicit)
> - **0.65** — weak (naming similarity only)
> - **0.55** — speculative

## 提取数据 schema

> 引用自原文（ARCHITECTURE.md）：
> ```json
> {
>   "nodes": [{"id": "unique_string", "label": "human name", "source_file": "path", "source_location": "L42"}],
>   "edges": [{"source": "id_a", "target": "id_b", "relation": "calls|imports|uses|...", "confidence": "EXTRACTED|INFERRED|AMBIGUOUS"}]
> }
> ```

## 对知识库的启发

这个混合提取策略直接映射到我们的摄入系统设计：
1. **代码**：用 `extract_code_skeleton.py` 提取骨架，无需 LLM → 对应 EXTRACTED
2. **文档/Wiki**：用 `[ingest]` 工作流通过 LLM 语义分块提取 → 对应 INFERRED
3. **知识卡片**：手动或 Agent 创建 → 需要人工标注置信度

关键洞察：**置信度标记不是可选的装饰，而是检索系统做决策的关键信号**。
