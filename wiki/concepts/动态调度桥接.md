# 动态调度桥接 (Dynamic-Dispatch Bridge)

## 解决的问题

静态 AST 解析（[[Tree-sitter AST解析引擎]]）有一个致命的盲区：**运行时才绑定的调用关系在静态分析中不可见。** 例如：

> 引用自原文（callback-edge-synthesis.md）：
> ```ts
> class Scene {
>   private callbacks = new Set<Callback>();
>   onUpdate(cb: Callback) { this.callbacks.add(cb); }          // REGISTRAR
>   triggerUpdate() { for (const cb of this.callbacks) cb(); }  // DISPATCHER
> }
> this.scene.onUpdate(this.triggerRender);                      // REGISTRATION SITE
> ```
> "The runtime edge `triggerUpdate → triggerRender` does not exist statically: `triggerUpdate`'s only literal call is `cb()` (anonymous)."

## 核心原则

> 引用自原文（CLAUDE.md）：
> "**Principle: partial coverage is WORSE than none.** Bridging one boundary but not the next reveals a hop the agent then drills + reads to finish. Measured on excalidraw: react-render alone *raised* reads to 5–7; only completing the flow (adding the jsx-child hop) dropped it to 0–1. **Always close the flow end-to-end and re-measure.**"

这是代码图谱最重要的设计原则之一：**半桥接比不桥接更糟糕**，因为它会把 Agent 引导到断裂的边界上，然后 Agent 必须回退到 Read 去重建剩余链路。

## 实现机制

CodeGraph 构建了一个**全图后处理 pass**，在所有基础边解析完成后运行：

### 1. Field Observer 通道 (Phase 1)

**触发条件：** 方法名匹配注册器模式 `^(on[A-Z]\w*|subscribe|addListener|register|watch|listen|addCallback)$` 且同文件存在分发器模式 `(emit|trigger|notify|dispatch|fire|publish|flush)`。

**算法流程：**
1. 按方法名候选注册器和分发器
2. 通过方法体确认：注册器有 `this.<F>.add|push|set(` 模式，分发器有 `for...of this.<F>` + call 模式
3. 按「同文件 + 同字段 `<F>`」配对
4. 从注册器的调用者中正则恢复被注册的回调参数名
5. 合成 `dispatcher → callback` 边

### 2. EventEmitter 通道 (Phase 2)

**触发条件：** 文件中同时存在 `.emit('event')` 和 `.on('event', handler)` 模式。

**精度控制：** 使用 **EventFanoutCap = 6** — 超过 6 个处理器或分发器的事件名（如 `error`/`change`）直接跳过，防止过度链接。

### 3. React 渲染桥接

> 引用自原文：
> "Channels today: callback/observer, EventEmitter, **React re-render** (`setState`→`render`), **JSX child** (`render`→child component), django ORM descriptor."

每种桥接都产生带有 `provenance:'heuristic'` 标记的合成边，并携带 `metadata.synthesizedBy` 元数据。

## 验证结果

> 引用自原文：
> "excalidraw got **1** synthesized edge out of 27k (the correct one); node count moved +3 after Phase 3 (no explosion)."
> "excalidraw: `trace(mutateElement, triggerRender)` = 3 hops; nodes 9,286 → 9,289"

## 与知识库的启示

动态调度桥接证明了一个重要的范式：**图谱中的边不一定来自确定性解析，启发式合成边同样有价值**，只要带有明确的 provenance 标记且能被工具链区分。这与我们的 [[知识库工业化升级_图索引检索系统]] 中基于 `[[双链]]` 构建的图谱异曲同工——关键不在于边的来源是否"精确"，而在于**图谱的连通性能否支撑端到端的检索**。
