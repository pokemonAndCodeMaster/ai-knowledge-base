# 🔀 前后端分离架构模式

> **定位**：解释前后端分离架构的核心原理，帮助团队理解"为什么前端和后端要分开"以及它们如何协作。
> **关联**：[[数据质量门户架构设计]] | [[全栈项目设计模式与实践]]

---

## 1. 什么是前后端分离

### 1.1 传统方式 vs 前后端分离

```
传统方式（服务端渲染 SSR）：
  浏览器请求 → 服务器生成完整 HTML → 返回给浏览器
  每次操作都要刷新整个页面

  Python 框架：Django 模板、Flask Jinja2
  就像 Django 的 render(request, 'template.html', context)

前后端分离（SPA 单页面应用）：
  1. 浏览器首次请求 → 服务器返回一个空 HTML + JavaScript 文件
  2. JavaScript 在浏览器中运行，构建出页面
  3. 需要数据时，JavaScript 发 HTTP 请求到后端 API
  4. 后端只返回 JSON 数据，不返回 HTML
  5. JavaScript 用 JSON 数据更新页面（不刷新！）
```

### 1.2 为什么选择前后端分离

| 维度 | 传统方式 | 前后端分离 |
|------|---------|-----------|
| 页面切换 | 每次都白屏刷新 | 无刷新，瞬间切换 |
| 开发分工 | 前后端代码混在一起 | 前端独立开发，后端独立开发 |
| 复用性 | 后端只能给浏览器用 | 后端 API 可以同时给 Web、App、小程序用 |
| 部署 | 一起部署 | 可以独立部署、独立扩容 |
| 适用场景 | 内容展示类（博客、新闻） | 交互密集型（管理后台、数据系统） |

**我们选前后端分离的原因**：数据质量系统是典型的管理后台，需要大量表格、表单、图表交互。用户需要频繁切换页面和操作数据，前后端分离的 SPA 体验远好于传统方式。

## 2. SPA（Single Page Application）原理

### 2.1 工作流程

```
第一次访问 http://your-server/：
  ┌─────────────┐        ┌─────────────┐
  │  浏览器      │ ────── │  Nginx/     │
  │             │ GET /  │  静态服务器  │
  │             │ ◄───── │             │
  │ 收到：       │        │ 返回：       │
  │ index.html  │        │ index.html  │
  │ + app.js    │        │ + app.js    │
  │ + style.css │        │ + style.css │
  └─────────────┘        └─────────────┘
       │
       │ JavaScript 运行，渲染出页面
       │ 用户点击"大模型质检"
       │ URL 变成 /llm-qc（但不刷新页面！）
       │ Vue Router 匹配到 LlmQcDashboard 组件
       │ 组件发请求获取数据
       ▼
  ┌─────────────┐           ┌─────────────┐
  │  浏览器      │           │  FastAPI     │
  │  (Vue 应用)  │ GET /api/ │  后端服务器  │
  │             │ tasks     │             │
  │             │ ◄──────── │  返回 JSON   │
  │  渲染表格    │           │             │
  └─────────────┘           └─────────────┘
```

### 2.2 为什么叫"单页面"

```
index.html 只有这么简单：

<!DOCTYPE html>
<html>
<head>
  <title>数据质量门户</title>
</head>
<body>
  <div id="app"></div>          <!-- 就这一个空的 div -->
  <script src="/assets/app.js"></script>  <!-- JavaScript 会填充这个 div -->
</body>
</html>

所有页面切换都是 JavaScript 在操控这个 div 的内容，
浏览器始终只有这一个 HTML 页面 —— 所以叫"单页面应用"。
```

## 3. RESTful API 设计

### 3.1 核心原则

REST（Representational State Transfer）是一种 API 设计风格。核心思想：**把后端的数据当作"资源"，用 HTTP 方法表示对资源的操作**。

```
HTTP 方法       对应操作      Python 类比
──────────     ─────────    ──────────────
GET            查询（读）    SELECT
POST           创建（增）    INSERT
PUT            整体更新      UPDATE（全字段）
PATCH          部分更新      UPDATE（部分字段）
DELETE         删除          DELETE
```

### 3.2 URL 设计规范

```
资源用名词（复数），操作用 HTTP 方法：

✅ 正确：
  GET    /api/v1/tasks          查询任务列表
  GET    /api/v1/tasks/123      查询任务详情
  POST   /api/v1/tasks          创建任务
  PUT    /api/v1/tasks/123      更新任务
  DELETE /api/v1/tasks/123      删除任务

❌ 错误（不要用动词做 URL）：
  GET    /api/v1/getTaskList
  POST   /api/v1/createTask
  POST   /api/v1/deleteTask/123

嵌套资源（子资源）：
  GET    /api/v1/tasks/123/results     任务 123 的质检结果
  POST   /api/v1/tasks/123/run         执行任务 123

查询参数用于筛选、排序、分页：
  GET    /api/v1/tasks?status=pending&page=1&size=20&sort=-created_at
```

### 3.3 状态码

```
200 OK         — 请求成功
201 Created    — 创建成功（POST 响应）
204 No Content — 删除成功（没有返回体）
400 Bad Request — 请求参数错误
401 Unauthorized — 未登录
403 Forbidden   — 无权限
404 Not Found   — 资源不存在
500 Server Error — 服务器内部错误
```

## 4. CORS 跨域 — 前后端分离必须理解的概念

### 4.1 什么是跨域

```
开发时：
  前端运行在 http://localhost:5173（Vite 开发服务器）
  后端运行在 http://localhost:8000（FastAPI）

浏览器的安全策略：
  从 localhost:5173 发请求到 localhost:8000 → 端口不同 → 跨域！
  浏览器会阻止这个请求！

解决方案：后端配置 CORS（允许跨域请求）
```

### 4.2 FastAPI CORS 配置

```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173"],  # 允许的前端地址
    allow_methods=["*"],                      # 允许所有 HTTP 方法
    allow_headers=["*"],                      # 允许所有请求头
)
```

### 4.3 生产环境的解决方案

```
生产环境通常用 Nginx 做反向代理，前端和后端共享同一个域名：

                    ┌─────────────────────────────┐
                    │         Nginx                │
  浏览器 ─── HTTPS ─── │                             │
                    │  / ──── 前端静态文件            │
                    │  /api ── 转发到 FastAPI 后端    │
                    └─────────────────────────────┘

这样前端请求 /api/xxx 不再跨域，CORS 问题自然消失。
```

## 5. 前后端协作流程

```
1. 定义接口：前后端约定 API 的 URL、参数、返回格式
   → 后端可以用 FastAPI 自动生成的 Swagger 文档
   → http://localhost:8000/docs

2. 并行开发：
   → 后端开发 API 并测试
   → 前端开发页面，用 Mock 数据先做

3. 联调：前端改 baseURL 指向后端，实际请求
   → 检查数据格式是否一致
   → 检查异常场景处理

4. 部署：打包前端静态文件 + 启动后端服务
```
