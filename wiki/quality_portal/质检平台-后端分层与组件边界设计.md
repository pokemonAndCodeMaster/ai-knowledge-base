# 质检平台后端分层与组件边界设计

← 总入口：[[质检一站式平台人工质检模块整体架构]]。相关：[[质检平台-领域模型层设计]]、[[质检平台-Repository与数据库访问设计]]、[[质检平台-Delta调用与状态回查设计]]。

## 1. 初衷

来源项目的能力散落在批处理脚本、数据库工具、Delta API 调用和看板中。新平台需要把它们串成可从前端调用的用例，但不能把所有逻辑塞进 Router，也不应为小模块照搬完整 DDD/六边形架构。

因此采用四层简单结构：HTTP 边界、应用编排、纯规则、数据/外部调用。

## 3. 组件职责

| 组件 | 应该做 | 不应该做 |
|---|---|---|
| Router | 读取请求、Depends 注入、调用 Service、映射响应 | SQL、采样算法、通过率判断 |
| Pydantic Schema | HTTP 字段、范围校验、OpenAPI 文档 | 数据库行模型、平台 SDK 调用 |
| AssignmentService | 串联快照、采样、task 查询、权限后的执行 | 自己实现 SQL 或随机算法 |
| StatService | 从任务级记录聚合并 UPSERT 快照 | 修改 Delta 任务状态 |
| ExecutionService | 预览规则结论、确认、调用 Delta、触发/等待回查 | 在 Router 中散落阈值分支 |
| PersonnelService | 人员 CRUD、调组、操作日志、未进组预警 | 统计 SQL 复制到每个页面 |
| Sampler | 输入最小单元计数，输出配额 | 查询数据库、调用 API |
| PassRule | 输入指标，输出决定和解释 | 写快照、发请求 |
| Repository | 参数化 SQL、行映射、单库事务 | 决定业务上是否允许执行 |
| DeltaClient | 请求封装、超时、响应解析 | 采样、规则判断、本地 SQL |

## 4. 依赖方向

```text
Router → Service → Sampler/Rule
                 → Repository → src/database
                 → DeltaClient → Delta平台

src/config → deps / src/database / DeltaClient
```

规则层不反向 import Router、Service、Repository。Repository 通过构造参数接收 `PostgresConnector`，不得自行创建连接池。

## 5. 为什么不用 ports/adapters/domain 套件

这些模式适合多个可替换基础设施、复杂领域状态机或大团队并行开发。当前只有一个 PostgreSQL 公共模块、一个 Delta 平台和少量规则；提前创建接口目录会增加导航成本，并把简单调用包装成多层转发。

当前替代方案：

- 外部平台封装直称 `delta_client.py`；
- 数据访问集中在共享 `repository.py` 的多个小类；
- 数据结构就近定义，复用后移到模块 `models.py`；
- 单元测试通过构造参数注入 fake repository/client，不要求先定义 Protocol。

当出现第二个可替换平台或测试替身难以注入时，再抽接口，不以“未来可能”作为现在的目录成本。

## 6. Service 的编排边界

以验收分配为例：

1. Router 完成 Schema 校验和权限依赖。
2. AssignmentService 查询快照。
3. Sampler 计算配额。
4. AcceptanceTaskRepository 查询 task_ids。
5. preview 只返回，不产生外部副作用。
6. execute 重查状态，再调用 DeltaClient。
7. Service 返回即时成功/跳过/失败；实际成功量由后续回查刷新。

Service 是唯一知道完整用例顺序的组件，这正是其高内聚点。

## 7. 生命周期与配置

- `src/api/app.py` 管理 FastAPI 启停和共享资源关闭。
- `src/api/deps.py` 构造 Repository、DeltaClient、Service，便于测试覆盖。
- `src/config` 提供数据库名、Delta 基址、超时和 mock 开关；密钥只从环境变量进入。
- `src/database` 继续管理连接池和健康检查。

## 8. 完成标准

- Router 不出现 SQL 和阈值计算。
- Sampler/Rule 单测无需 FastAPI、数据库或网络。
- Service 可注入 fake Repository/DeltaClient。
- 所有外部写操作均有后端权限校验和状态重查。
- import 检查、API 冒烟和三条端到端示例通过。
