# 人工质检-⑤任务分配

> 将waitingAssign状态的标注任务批量分配给标注员(screener)、审核员(reviewer)、验收人(acceptor)。

← [[人工质检-数据源与任务创建]] | [[人工质检-Hub]]

## 基本信息

| 维度 | 详情 |
|------|------|
| 核心代码 | `manual_label/label_task_manage/assign_quality_check.py` → `ListAssign()` / `ListAssignFinal()` |
| 触发方式 | 手动执行脚本，两步确认(Dry run→人工确认→Wet run) |

## 输入

| 数据源 | 完整表名 | 用途 |
|--------|---------|------|
| 人员配置 | `company_data.yaml`(本地) | 公司→员工映射 / 公司→审核员映射 |
| 人员名单 | `待分配数据人员名单.xlsx`(本地) | 标注员+需求数量 |
| 待分配任务 | `app_gy1.delta.ods_t_label_screening_task_datalake` | task_screener IS NULL |

## 输出

| 目标 | 说明 |
|------|------|
| Delta API | `batch_assign` → 写入screener/reviewer/acceptor |
| 分配日志 | `assign_log_{timestamp}.xlsx` |

## 分配策略

1. 从company_data.yaml加载公司→员工映射(company_employee_dict)和公司→审核员映射(company_reviewer_dict)
2. 查询task_screener IS NULL的未分配任务
3. 对每个标注员：判断所属公司→轮询选择同公司审核员(跳过自己)
4. 软通公司审核员固定为`w00566553`
5. 检查该标注员当前待筛选+筛选中任务数不超过limit
6. 两步确认：先Dry run(预览)→人工确认→Wet run(正式分配)

## 关键SQL

```sql
-- 查询待分配任务
SELECT task_creator, task_name, id, task_screener
FROM delta.ods_t_label_screening_task_datalake
WHERE task_name LIKE '驾驶行为质检_{data_set}%'
AND create_time > 1760803200000000
AND task_screener IS NULL AND del_flag = 0;

-- 检查标注员当前任务数
SELECT count(id) FROM delta.ods_t_label_screening_task_datalake
WHERE task_name LIKE '驾驶行为%' AND task_screener = '{screener_id}'
AND (task_status = 64 or task_status = 65);
```
