## 2. 已冻结决策

- 快照最小行：日 × scene × 当日组 × 标注员；不存 NULL 标注员汇总行。
- 快照算采样配额，任务级表选择具体 task_ids。
- execute 使用 preview 原 task_ids，并在执行前重查状态。
- 外部操作后回查任务状态，实际量不等于请求量。
- 人员单项目，权限按模块等级。
- 数据结构就近定义、复用后上移。
- 共享 Repository 按数据源分小类；Delta 调用使用 `delta_client.py`。
- 不引入通用操作台账、ports/adapters 和数据库规则引擎。

## 3. Phase 2.5 剩余门槛

1. 从现有实现确认 Delta 接口 URL、认证、请求/响应、批量上限和错误码。
2. 确认 waiting_review、已完成、打回后的准确状态字段和值。
3. 确认通过/打回最终执行范围。
4. 把 preview/execute Schema 写成可 Review 的字段级契约。
5. 用三个示例固定：全部成功、部分失败回查、重复执行跳过。

## 4. Phase 3 推荐纵切顺序

### 3A：纯规则

实现 sampler、pass_rules 和边界测试。此阶段不需要数据库和 Delta。

### 3B：统计只读链

实现 SnapshotRepository、StatService、统计查询 API，使用临时 PostgreSQL 和样例任务记录。

### 3C：验收分配闭环

实现 preview → task_ids → execute → fake Delta → 状态回查 → 实际量刷新。这是首条真正端到端验收路径。

### 3D：通过/打回闭环

实现规则 preview、人工确认、通过/打回调用、状态回查。

### 3E：人力与权限

实现人员 CRUD、调组日志、模块等级权限和 mock 身份。

## 5. Phase 3 完成标准

- 纯规则测试覆盖阈值、数据不足和取整。
- Repository 集成测试在真实 PostgreSQL 临时实例通过。
- FastAPI 启动，OpenAPI 展示当前端点。
- 分配闭环覆盖成功、部分失败、重复执行。
- 通过/打回拒绝 PENDING 和无权限用户。
- 人员修改与 op_log 同一事务。
- 代码卡、index、log 和图谱同步更新。

## 6. Phase 4 与 5

前端按 [[质检平台-人工质检前端页面与状态设计]] 实现；联调以用户链路为准，不以“Swagger 能打开”代替端到端成功。

## 7. 风险

- Delta 接口资料不足是当前唯一实质外部阻塞。
- 上游中间表刷新存在延迟，UI 必须展示 computed_at/回查状态。
- 旧流程文档来自上游快照，字段和路径不能直接冒充当前仓库实现。
