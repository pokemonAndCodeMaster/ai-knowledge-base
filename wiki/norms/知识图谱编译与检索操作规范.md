# 知识图谱编译与检索操作规范

## 规范：必须触发重编译的时机

以下任何一种情况发生后，**必须**运行 `python scripts/compile_graph.py`：

| 触发事件 | 说明 |
|----------|------|
| `[ingest]` 新建/修改卡片 | 新卡片不会自动进入图索引 |
| `[ingest]` 修改 `[[双链]]` | 链接关系变更后图谱失效 |
| `[health]` 体检前 | 确保检测数据最新 |
| `[compile]` 主动触发 | 用户主动刷新 |
| 手动修改 wiki/*.md 后 | 图索引与文件不同步 |

**禁止**：在图索引未重编译的情况下运行 `query_graph.py`（可能返回过期结果）。

---

## 规范：code_module 卡片必须填写 code_hash

**背景**：代码文件会变更，但卡片不会自动感知。

**操作步骤**：
1. 创建 `code_module` 类型卡片时，在 frontmatter 中填写：
   ```yaml
   related_code: ["scripts/compile_graph.py"]
   code_hash: ""  # 先留空
   ```
2. 运行 `python scripts/compile_graph.py` 编译
3. 运行 `python scripts/check_staleness.py --code-only` 获取当前 hash
4. 将 hash 值填入卡片 `code_hash` 字段
5. 重新编译

**当 check_staleness 报告 `code_changed`**：
1. 用 `git diff <code_file>` 查看变更
2. Agent 判断变更是否影响卡片描述的内容（接口变更 > 实现细节）
3. 若需要：更新卡片正文 → 更新 `code_hash` → 重编译
4. 若不需要：只更新 `code_hash` → 重编译

## 规范：trigger_keywords 必须填写

**背景**：trigger_keywords 是 Seed 发现权重最高（+3.0）的维度，直接影响召回率。

**填写原则**：
- 填写"用户问什么问题时这张卡片应该被召回"的关键词
- 3-8 个关键词，不是卡片主题词，而是**触发场景词**
- 示例（compile_graph脚本 卡片）：
  ```yaml
  trigger_keywords:
    - compile_graph
    - 编译知识图谱
    - 图索引
    - 构建索引
    - 重建图谱
  ```
- ✅ 好：具体的操作词、场景词
- ❌ 差：过于通用（"知识"、"管理"）或与 tags 完全重复

---

## 规范：断链不应超过 50 条

当 `compile_graph.py` 报告断链 >50 条时，应运行 `[health]` 体检，重点检查：
1. 是否有卡片被重命名但引用未更新
2. 是否有 `[[引用]]` 指向尚未创建的卡片（缺页）

---

## 规范：.wiki_graph.json 纳入 git

```bash
# 确保 .gitignore 不排除此文件
# .wiki_graph.json 应在每次 ingest 后随卡片一起 commit
git add .wiki_graph.json wiki/ && git commit -m "feat(km): [ingest] 卡片名称"
```
