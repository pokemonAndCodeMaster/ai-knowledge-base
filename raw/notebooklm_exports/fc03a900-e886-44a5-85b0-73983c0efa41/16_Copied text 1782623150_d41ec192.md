## 关键结论

- 前端不能直接复用 Python 类；成熟 Python 能力要由 Application Service 编排，再通过 FastAPI Router 暴露成 HTTP API。
- 后端返回业务数据，不返回 ECharts option；前端负责把业务数据转换成图表配置。
- View 负责页面状态和用户动作，业务图表/表格组件负责渲染，`api.ts` 负责和后端通信。
- 公共能力要下沉：配置、数据库、HTTP client、响应 schema、通用表格、图表壳、状态标签都不属于单个业务模块。
- 新页签开发必须能端到端跑通：PostgreSQL -> Repository -> Application Service -> FastAPI -> 前端 API -> View -> 表格/图表。

## 落地路线

### P0：后端闭环

先实现 `GET /api/v1/llm-qc/tasks`：

- 后端 schema：`src/api/schemas/llm_qc.py`
- 后端 router：`src/api/routers/llm_qc.py`
- 业务 service：`src/llm_qc/application/task_service.py`
- 数据访问 repository：`src/llm_qc/repositories/task_repository.py`
- 数据库复用：[[PostgreSQL数据库公共模块]]

### P1：前端页签

再实现 `/llm-qc/tasks`：

- 前端类型：`src/frontend/src/features/llm-qc/types.ts`
- 前端 API：`src/frontend/src/features/llm-qc/api.ts`
- 前端页面：`src/frontend/src/features/llm-qc/views/TaskListView.vue`
- 前端路由：`src/frontend/src/features/llm-qc/routes.ts`

### P2：可视化和复用

表格跑通后再加可视化：

- 图表壳：`src/frontend/src/shared/charts/BaseChart.vue`
- 图表 option：`src/frontend/src/shared/charts/options.ts`
- 业务图表：`src/frontend/src/features/llm-qc/components/TaskStatusChart.vue`
